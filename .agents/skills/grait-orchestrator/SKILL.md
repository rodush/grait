# Orchestrate local delivery

Read AGENTS.md, docs/workflow.md, docs/operations.md, and docs/worktrees.md. You are the parent session in the user's Codex, Claude Code, or GitHub Copilot CLI harness. All specialists and commands run on this host; use the harness's existing login. Never dispatch an AI workflow to GitHub or request a provider API key. Use Copilot's local sub-agents, never its /delegate or cloud-agent flows.

1. Inspect `npm run orchestrator -- status` and current issue/PR discussions. Resume existing claims at their recorded handoff and prioritize pending Review work. Report any Review story waiting for a human or an external dependency. Follow the admission rules in `docs/workflow.md` and honor the claim command's checks. Use Ready as the source of new claims. When Ready is below `maxReady` in `workflow.config.json` (five by default), use available triage workers to replenish it from Backlog without delaying eligible Ready claims. Record current assessments with `npm run orchestrator -- ready --issue N --file PATH`. Keep blocked stories in Backlog and reassess when their dependencies complete.
2. Select eligible Ready stories across the Project without waiting for the operator to name tickets. Use explicit Project priorities and dependency order, then Project queue order when priorities are equal. Reserve each story with `npm run orchestrator -- claim --issue N` before starting it. Continue claiming and dispatching independent stories while the Project has In Progress capacity and a worker is available, even when other claims are active. Respect the configured worker limit independently of the five-story Project cap. If a candidate is blocked, paused, or no longer Ready, report the reason and consider the next eligible candidate. Refresh the queue when a claim, handoff, review, or merge changes capacity or eligibility. Stop admitting work when a Project-wide gate applies, capacity is exhausted, or no eligible Ready story remains.
3. Prepare `npm run orchestrator -- worktree --issue N`. Assign its absolute path, branch, acceptance digest, base SHA, writable paths, and next owner. The tester and implementer share this SAME worktree sequentially. Start native sub-agents with that explicit assignment, or use `npm run orchestrator -- worker --issue N --role test|implement|fix` to launch a native session there. Do not use a fresh default-branch worktree for an implementation handoff. When Copilot Auto would ignore an explicit tester/implementer model profile, use the worker-session command so that the native --model option selects that profile.
4. For testable work, delegate the tester first. Independently run and record Red, then transfer exclusive ownership to the implementer. Independently run full-suite Green before review. Use the handoff and verification commands in docs/tdd.md. The implementer receives only stable failure IDs and explicitly public sanitized observations; never send test source or fixture internals.
5. Complete the accepted scope, relevant documentation, and required validation before publishing a normal PR. Publish committed work using `npm run github -- push --issue N`, then `npm run github -- pr --issue N --title 'feat: ...' --body-file PATH`. Normal PRs are the default and require independent Green for the exact head or an accepted reasoned triage TDD exemption. Run `npm run orchestrator -- sync --pr N` to move the delivery to Review. Use `--draft` only when the user explicitly requests work in progress or early feedback; do not substitute a draft for completing the task. After completing that draft's scope and required validation, use `npm run orchestrator -- ready-pr --pr N` to promote its exact accepted head and synchronize Review. Report any blocker that prevents completion.
6. Delegate grait-review in a separate worktree at the exact PR head, using trusted default-branch policy. Publish its structured payload through `npm run orchestrator -- review --pr N --file /dev/stdin` (or a temporary transport file when required by the host). Verify that the formal review and inline findings are visible on GitHub; a local report alone is not a completed review. Tester and fixer read the PR conversation directly through GitHub CLI/API. Keep follow-up replies, fix commits, and validation evidence in the original threads. After the independent reviewer verifies a fix, ensure its agent thread is marked Resolved through an authorized reviewer session; leave human objections for humans to resolve. If resolution is unavailable, report it as pending. Follow the returned decision. Incremental fixes stay Review; a rethink must reacquire In Progress capacity first. Humans merge and release. After human merge, run `npm run orchestrator -- sync --pr N` and clean up only task-owned clean worktrees.

Before every stage, recheck repository enablement, issue/PR pause labels, current head, and ownership. Stop on conflicting instructions, an uncertain external write, repeated blockers, oscillation, exhausted review rounds, or unavailable evidence. Save committed handoff/checkpoint evidence on GitHub before ending a subscription-limited session. Do not busy-loop model calls while waiting for humans, CI, or allowance resets. Only one host may coordinate a Project; locks serialize local commands, not independent hosts.
